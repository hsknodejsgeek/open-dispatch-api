# infra

OpenTofu IaC for opendispatch — single EC2 instance running Docker (Postgres) + nginx as a reverse proxy. App containers (web/api) are deployed separately by CI/CD, not by OpenTofu.

## What this provisions

- **Networking**: a minimal VPC with one public subnet, an internet gateway, and a route table (no NAT/private subnets — everything runs on one box).
- **EC2 instance**: `t3.medium`, Amazon Linux 2023, 30GB gp3 root volume, Elastic IP for a stable public address.
- **Security group**: only ports `22` (SSH) and `80` (HTTP) are open. App ports `3000`/`3001` are never exposed to the internet — only reachable on `127.0.0.1` and proxied through nginx.
- **SSH key pair**: generated by OpenTofu at apply time; the private key is written locally to `infra/opendispatch-<environment>-key.pem` (gitignored — never commit it).
- **Bootstrap (`user_data` → `scripts/bootstrap.sh.tpl`)**, runs on first boot and is safe to re-run:
  1. Installs Docker + the Compose plugin — skipped if already installed.
  2. Writes `docker-compose.postgres.yml` to `/opt/opendispatch` and starts **Postgres only** (16-alpine, data in a named Docker volume, credentials from variables below).
  3. Installs nginx — skipped if already installed — and writes `/etc/nginx/conf.d/opendispatch.conf`:
     - `/web/*` → `127.0.0.1:3000` (frontend)
     - `/api/*` → `127.0.0.1:3001` (backend)

## What this does NOT do

Deploying the actual web/api app containers, syncing `.env` files, and restarting the app on every push is handled by your GitHub Actions CI/CD workflow (SSH or SSM into the box), not by OpenTofu. OpenTofu's job ends once the instance, networking, Docker, Postgres, and nginx exist.

## Files

| File | Purpose |
|---|---|
| `main.tf` | VPC, subnet, security group, key pair, EC2 instance, Elastic IP |
| `variables.tf` | Region, environment, instance size, volume size, DB creds/ports, app ports |
| `outputs.tf` | Public IP, SSH command, path to the generated private key |
| `scripts/bootstrap.sh.tpl` | Idempotent boot script: Docker, Postgres compose, nginx config |
| `templates/` | Reference copies of the compose/nginx config (the live versions are inlined in `bootstrap.sh.tpl`) |

## Usage

```bash
cd infra
tofu init
tofu plan
tofu apply
```

Override sensitive/environment-specific values via a `.tfvars` file (gitignored) or `TF_VAR_*` env vars — never commit real values for `db_password`:

```hcl
# infra/terraform.tfvars (gitignored)
environment      = "production"
ssh_allowed_cidr = "1.2.3.4/32"   # lock SSH down to your IP, not 0.0.0.0/0
db_password      = "..."
```

```bash
tofu apply -var-file=terraform.tfvars
```

After apply:

```bash
tofu output public_ip          # http://<public_ip>/web/*  and  /api/*
tofu output ssh_command        # ssh -i infra/<key>.pem ec2-user@<public_ip>
```

## Variables

| Variable | Default | Description |
|---|---|---|
| `aws_region` | `us-east-1` | AWS region |
| `environment` | `staging` | `staging` or `production` |
| `vpc_cidr` | `10.0.0.0/16` | VPC CIDR |
| `public_subnet_cidr` | `10.0.0.0/24` | Public subnet CIDR |
| `ssh_allowed_cidr` | `0.0.0.0/0` | CIDR allowed to SSH — set to your IP |
| `instance_type` | `t3.medium` | EC2 instance type |
| `root_volume_size` | `30` | Root EBS volume size (GB) |
| `db_name` | `opendispatch_db` | Postgres database name |
| `db_username` | `postgres` | Postgres username |
| `db_password` | `changeme-in-tfvars` | Postgres password — override, never commit |
| `db_port` | `5432` | Host port Postgres is published on |
| `web_port` | `3000` | Port the frontend app listens on (nginx `/web/*`) |
| `api_port` | `3001` | Port the API app listens on (nginx `/api/*`) |

## Outputs

| Output | Description |
|---|---|
| `public_ip` | Elastic IP of the instance |
| `ssh_command` | Ready-to-use SSH command |
| `private_key_path` | Local path to the generated private key (for SSH and the CI/CD deploy secret) |
